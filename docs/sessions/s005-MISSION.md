# s005 · Agents that drive PRs home

## Goal
Finish M2. After this session, one feature of the operator's project goes `pr → fix → verify → post → approve → land` with the operator's only actions being the verify tick, the confirmation of the Slack post, and the approval. Three tracks that share only `packages/protocol`: `engine` builds the pipeline commands; `ext` builds the Spinner pi extension and the agent plumbing (inbox delivery, file-watcher steers, the fixer role); `ui` builds the mission panel, the threads view and the PR buttons. The daemon and the UI from s003 are the base; the CLI calls the same `actions` module as the routes.

- [x] `threads/<repo>-<pr>.md` renders from GitHub; `spinner fix` starts or steers the fixer agent, which replies to, fixes or flags every open thread through the `thread_*` tools and never skips one
- [x] `spinner post` composes the Slack message, shows it, posts as the operator on confirmation, stores the post URL; the board shows reviewer activity from the post's replies

## Contracts & decisions
- 2026-10-28 the operator: Spinner acts as the operator. PRs open as the operator's `gh` login; the Slack post is sent with the operator's user token (`SLACK_USER_TOKEN` in the environment; never in a file); the approval is the operator's review. The daemon never posts, approves or lands on its own; each is a job the operator starts, and `post` and `approve` show what they will send before they send it.
- 2026-10-28 the operator: after any push to a PR, the operator's approval is asked again (`needs_human: approve <repo>#<n>`), never re-applied by Spinner. Peer approvals count as GitHub counts them; a stale one is shown as stale.
- 2026-10-28 the operator: a thread is never skipped. The fixer replies to every open thread; it resolves only after its fix is pushed and checks are green; it flags design questions, disagreements and out-of-session changes. With `threads.resolve_human: false` it replies to human threads and leaves them open.
- 2026-10-28 the operator: the fixer never force-pushes and never rebases a branch with unpushed agent work; `land` rebases through a job that stops on conflict with `needs_human`.
- 2026-10-28 the operator: mission writes go through the daemon (`PUT /sessions/:dir/mission/section`, one writer at a time). The extension's `mission_*` tools call it; the UI calls it; a hand edit still works for an agent without the extension.
- 2026-10-28 the operator: `cli.ts` and `daemon/src/index.ts` are shared-append registries, one line per owner; `src/agents/**` belongs to ext in this session; engine calls `agents` through its exported functions.
