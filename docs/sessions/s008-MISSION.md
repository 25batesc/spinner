- 12:56 desktop: bridge additions, in `packages/protocol/src/desktop-bridge.ts` at b98e29d. `SpinnerDesktop` gains `panes: DesktopPanes`.
  - `previews.popOut(key)`: moves the key's existing `WebContentsView` into its own native window, no reload. The view must exist (one `set` before). While popped out, `set(key, …)` only updates the URL; `show`/`hide` of that key are ignored, so the pane may keep rendering its box or unmount it. A second call focuses the window.
  - `previews.dockBack(key)`: closes the window, puts the view back in the main window hidden; the next `set` from the pane places and shows it. A `pane.docked` event follows (same as the close button).
  - `panes.popOut(pane, session)` with `pane: "sessions" | "agents"`: a `BrowserWindow` with the bridge preloaded on `<daemon>/?pane=<pane>&session=<session>`. One window per `(pane, session)`; a second call focuses it. For the previews pane the UI calls `previews.popOut(key)` with the selected tab's key.
  - `panes.dockBack(pane, session)`: closes that window; `pane.docked` follows. No-op if absent. Usable from inside the popped-out page (it has the bridge).
  - `panes.list(): Promise<PoppedPane[]>`: every popped-out window (previews with `key`), so a reloaded renderer catches up.
  - `panes.subscribe(listener)`: events `{ type: "docked", pane, session, key? }` whenever a pop-out ends: by `dockBack`, by the window's close button, or by the session closing. The main window's page treats the event as idempotent and restores the pane in place.
  - Types: `PaneName`, `PoppedPane`, `PaneEvent`.

- 13:45 desktop: browser-bar bridge additions, in `packages/protocol/src/desktop-bridge.ts` at b707388, on `DesktopPreviews`:
  - `navigate(key, url)`: loads an http(s) URL in the view; `back(key)`, `forward(key)`: the view's history. Navigation stays in the view; `target=_blank` still opens the external browser. None change the pane's `set` URL, so a later `set` with the same URL only moves the view (same as a click inside the page).
  - `zoom(key, "in" | "out" | "reset")`: one Chromium zoom level per step (20 %), reset is 100 %. Chromium keeps zoom per origin, so views of one host share it.
  - `find(key, text | null)`: `findInPage`; the same text again finds the next match; resolves with `{ matches, active }` (final count; `active` is 1-based, 0 when none) or null when `text` is null (clears search and selection) or the view does not exist.
  - `clearStorage(key)`: `session.clearStorageData({ origin })` for the view's current origin only, then reload. The renderer confirms with the user first.
  - Event through `previews.subscribe`: `{ type: "navigated", key, url, title, canGoBack, canGoForward, loading }` on `did-navigate`, `did-navigate-in-page`, `page-title-updated`, `did-start-loading`, `did-stop-loading`. A failed load's error page reports the failed URL.
  - Types: `ZoomDirection`, `FindResult`, `PreviewNavigation`.
