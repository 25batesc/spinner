# s009 · Agent terminals: the pi TUI in each agent tab

## Goal
Today each agent is a `pi --mode rpc` child and the agents pane renders its events as a thin chat (`AgentChat.tsx`, 300-character cells, no tool output, no slash commands, no pi widgets). The operator wants to talk to each agent the way he talks to pi in a terminal. After this session an agent tab is pi's own terminal UI: the daemon runs `pi` interactively in a pseudo-terminal in the agent's worktree, the web UI and the desktop app render it with xterm.js, keystrokes go up and output comes down over one WebSocket, and the Spinner pi extension inside that pi is the daemon's channel for `prompt`, `steer` and state. The RPC harness stays as the headless path (tests, `agents.harness: rpc`). Two agents: `engine` (daemon, extension, protocol) and `ui` (the terminal tab).

- 16:20 engine (Plan 1, the tty contract):
  - **`config.yaml`**: `agents: { harness: tty | rpc }`, default `tty`; the environment override is `SPINNER_AGENTS_HARNESS`. `session.yaml` `agents.<name>.harness` records `tty` or `rpc` (the legacy value `pi` reads as `rpc`); the UI picks the terminal or the chat from that field in `SessionView.session.agents[name].harness`. `AgentSpec` gains `started?: string` (pi's start time as `ps -o lstart=` prints it) next to `pid`.
  - **tty WebSocket**: `GET /sessions/:dir/agents/:name/tty` upgrades (same `ws` server as `/events`). Before the upgrade the daemon answers plain HTTP on a problem: 404 (no session, no agent, or the agent is not running), 409 (`rpc` agent, or 8 attachments already). After the upgrade the daemon sends one binary frame with the scrollback (0 to 65536 bytes, raw pty bytes, can start mid-escape), then one binary frame per pty chunk. Client → daemon: a binary frame is keystrokes to the pty, unchanged; a text frame is JSON, the only shape is `{"resize":{"cols":n,"rows":n}}` (1 ≤ n ≤ 1000; anything else closes with 1008). Daemon → client text frames: `{"exit":{"code":n|null}}` once the pty child is gone, then close 1000. The pty's size is the last resize from any client; the first client's resize sets the initial size, else 120×40. On `stop` the daemon closes every attachment with 1000 after the `exit` frame.
  - **commands long-poll** (extension → daemon): `GET /sessions/:dir/agents/:name/commands?ack=<id>&disposition=<text>`; the `ack` pair is absent on the first call and names the command the extension just acted on. The daemon holds the request up to 30 s; it answers 200 `{"command":{"id":"c-1","type":"prompt"|"steer"|"abort","text":"..."}}` (one command per response; `text` absent for `abort`) or 204 when none arrived in time. The extension acts (`prompt` → `pi.sendUserMessage(text)` when idle, `{deliverAs:"followUp"}` when busy; `steer` → `pi.sendUserMessage(text, {deliverAs:"steer"})`; `abort` → `ctx.abort()`) and reopens the poll at once with the ack. The `prompt` / `steer` HTTP routes resolve with the acked disposition (`started` when pi was idle, `queued` when busy); without an ack in 30 s they answer 504. Only the tty harness serves this path; for an rpc agent it is 409.
  - **hello** (extension → daemon, once per pi start and after `/spinner-reload`): `POST /sessions/:dir/agents/:name/hello` `{"pid":n,"commands":[SlashCommandInfo]}` → 200 `{"ok":true}`. `commands()` on the handle returns the last posted list; `spawn`/`resume` resolve when hello arrives or 3 s after the pty started with pi still alive (pi can sit on a "Press any key" startup notice the operator answers in the tab; hello follows); a pty that exits inside those 3 s is a failed spawn (amended 16:47 after the e2e).
  - **events** (extension → daemon): `POST /sessions/:dir/agents/:name/events` `{"events":[PiEvent,...]}` → 202 `{"ok":true}`; body bound 8 MiB. The extension posts `agent_start`, `agent_end`, `agent_settled`, `turn_end`, `tool_execution_start`, `tool_execution_end`, each as pi hands it to the extension (the same fields the RPC stream carries). The manager's fold runs unchanged: `agent.event` on the bus per event, `busy`/`process: running` on `agent_start`, `agent.settled` and `process: idle` on `agent_settled`. `agent_settled` is in the list because the fold keys on it, not on `agent_end`.
  - All three extension routes 404 when the agent is not hosted; the extension retries after 1 s. The extension runs this channel only when `SPINNER_HARNESS=tty` is in its environment; the daemon sets it, with `TERM=xterm-256color`, on the pty spawn.
  - **restart**: the pty master dies with the daemon, so the child gets SIGHUP. On start the daemon reads `agents.<name>.{pid,started}` for every agent whose `process` is not `exited`: a live identity gets SIGTERM (SIGKILL after 5 s), then the agent is `resume`d on the same `--session-id`; a dead one is `resume`d directly. The scrollback is empty after a restart; pi redraws the transcript on resume.
