# s003 · Daemon API + web UI, then the pi adapter

## Goal
Make the daemon the one place that knows every session's board facts and stack state, and give the operator a window per feature on top of it: sessions and board on the left, agent tabs in the middle, previews on the right. Everything the CLI can do today (`new`, `adopt`, `up`, `down`, `close`, `verify`) becomes a daemon action with progress over the event stream, and the UI drives it. Then the daemon learns to host pi agents (`PiRpcHarness`), and the agent tabs come alive. Two agents: `engine` (protocol, daemon, pi adapter) and `ui` (the web app). The CLI keeps working; it calls the same daemon code in-process.

- 13:50 engine: answer to the context-reload question. pi 1.4.0 reads context files (`AGENTS.md` chain) and `--append-system-prompt` (the brief) once, when its resource loader runs at startup: `dist/core/resource-loader.js` `loadProjectContextFiles` is called from the loader's load/`reload()`, and `dist/core/agent-session.js` `_rebuildSystemPrompt` reads the cached `getAgentsFiles()`; the per-request diff (`diffSystemPromptSections`) only patches what that cache holds. There is no RPC command for a reload (`dist/modes/rpc/rpc-types.d.ts` `RpcCommand` has none); `/reload` is a TUI command, and in RPC mode only an extension can call `ctx.reload()` (`dist/modes/rpc/rpc-mode.js`, `reload: async () => session.reload()`), after which the next request carries the new sections. So in v1 the daemon restarts the process after a context edit: `POST .../agents/:name/stop`, then `POST /sessions/:dir/agents { name }` again, which resumes the transcript by id (`--session-id <name>` opens or creates). The Spinner pi extension (M2) can add a `/spinner-reload` command that calls `ctx.reload()` and make this a prompt instead of a restart. Verified by reading those files and by the resume run in the 13:50 Log line.

Also: `NewSessionRequest.project` accepts a name that resolves under `local/`, `~/.spinner/projects/`, and `examples/` (the `GET /projects` names must round-trip); keep the path form too.
